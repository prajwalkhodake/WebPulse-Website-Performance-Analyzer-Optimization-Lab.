1. EXECUTIVE SUMMARY & ABSTRACT
================================================================================
WebPulse is an educational, portfolio-grade developer laboratory designed for 
pre-deployment web performance optimization, static code analysis, and interactive 
dependency modeling. 

Unlike conventional performance evaluation tools (such as Google PageSpeed Insights, 
GTmetrix, or WebPageTest) that require public DNS addresses and deployed servers, 
WebPulse allows developers, students, and engineers to upload raw ZIP archives of 
their website source code before committing to production.

The application securely ingests and extracts source archives, conducts multi-file 
static inspection across HTML, CSS, JavaScript, and multimedia assets, generates 
an interactive Cytoscape.js directed graph of internal asset relationships, spins 
up an isolated, ephemeral loopback server to execute true headless Chromium browser 
audits via Playwright, and produces deterministic, prioritized optimization 
recommendations. Furthermore, WebPulse supports multi-version tracking, enabling 
side-by-side comparative diffs that quantify payload byte savings, resolved issues, 
and Core Web Vitals metric improvements.

2. MOTIVATION & PROBLEM STATEMENT (THE PRE-DEPLOYMENT BLINDSPOT)
================================================================================
Modern web development places heavy emphasis on user experience, Core Web Vitals, 
and search engine rankings. However, developers face a significant architectural 
hurdle during active development:

1. THE PRE-DEPLOYMENT BLINDSPOT:
   Existing public audit tools exclusively accept publicly routable URLs 
   (e.g., https://example.com). Internal prototypes, student capstone projects, 
   localhost mockups, and corporate intranet applications cannot be evaluated.

2. LATE DEFECT DISCOVERY:
   Performance defects (such as render-blocking scripts in the <head>, uncompressed 
   raster images, missing responsive viewport meta tags, missing font-display swap 
   directives, and circular script imports) are routinely discovered only after 
   staging or production deployment, causing costly rework and degraded initial UX.

3. FRAGMENTATION OF TOOLING:
   Developers must typically stitch together multiple disjoint utilities: an AST 
   linter for static code, a dependency visualizer, and a browser profiler. There 
   is rarely a single unified environment that links static code issues with 
   measured network waterfall traces and version-over-version progression.

WebPulse bridges this gap by unifying static parsing, dependency visualization, 
sandboxed browser simulation, and release comparison into a single self-contained 
laboratory.

The primary engineering objectives of WebPulse include:

  React 18 components for dynamic controls and visualizations.

7. DETAILED MODULE BREAKDOWN (ALL 8 DEVELOPMENT PHASES)
================================================================================

PHASE 1: FOUNDATION, AUTHENTICATION & CORE WORKSPACE
- Modular Flask blueprint architecture:
  * `app/auth`: User registration, login, logout, profile update.
  * `app/main`: Public landing page, features showcase, technical about documentation.
  * `app/dashboard`: Multi-project workspace overview with aggregate counters.
  * `app/errors`: Custom 403 (Forbidden), 404 (Not Found), 413 (File Too Large), 
    and 500 (Internal Server Error) views.
- Security baseline: HTTPOnly, SameSite cookies, CSRF protection on all forms, 
  Scrypt password hashing, and secure HTTP response headers.

PHASE 2: PROJECT MANAGEMENT & ANTI-ZIP-SLIP INGESTION
- Multi-project containment: Users manage isolated projects with distinct entry points.
- Secure Archive Validator (`ArchiveValidator`):
  * Rejects files exceeding 50 MB quota.
  * Validates ZIP header integrity.
  * Scans every internal member path to block directory traversal attacks (Zip-Slip), 
    symbolic links pointing outside the extraction boundary, and absolute path injection.
- Isolated extraction: Files are uncompressed into private `storage/extracted/user_<id>/` 
  directories strictly outside the web document root.
- Automated file cataloging: Extracts file size, line counts, and mime classifications.

PHASE 3: STATIC CODE ANALYSIS ENGINE
- Deterministic static analyzer (`StaticAnalyzer`):
  * Inspects HTML using structural regex parsers for missing `<title>`, missing 
    `<meta name="viewport">`, render-blocking `<script>` tags in `<head>`, and 
    raster images missing `alt` attributes or `width`/`height` dimensions.
  * Inspects CSS for performance bottlenecks: synchronous `@import` statements, 
    oversized inline base64 image URIs, and missing `font-display: swap`.
  * Inspects JavaScript for un-deferred external scripts, missing error handling, 
    and heavy synchronous dependencies.
- Classifies all detected issues into standard severities (*Critical*, *Warning*, *Info*) 
  and categories (*Performance*, *Accessibility*, *Best Practices*, *SEO*).

PHASE 4: DEPENDENCY GRAPH & CYTOSCAPE MODELING
- Graph extraction service (`DependencyMapper`):
  * Discovers directed references between files:
    HTML -> Script (`<script src="...">`)
    HTML -> Stylesheet (`<link rel="stylesheet" href="...">`)
    HTML -> Image (`<img src="...">`)
    HTML -> Hyperlink (`<a href="...">`)
    CSS -> Font / Image (`url(...)`)
  * Resolves relative path targets and maps them to cataloged `project_files`.
- API endpoint (`GET /analysis/api/<version_id>/graph-data`):
  * Emits Cytoscape-compliant JSON payloads with node types, file sizes, in-degree, 
    out-degree, and connected edge attributes.

PHASE 5: MULTI-FACTOR SCORING & RECOMMENDATION ENGINE
- Score calculation (`AnalysisResult.calculate_health_score()`):
  * Base 100 points, deducting weighted penalties: Critical (-12 pts), Warning (-5 pts), 
    Info (-1 pt). Clamped to [0, 100].
- Recommendation prioritization engine (`RecommendationEngine`):
  * Groups related findings and maps them to deterministic optimization playbooks.
  * Calculates `priority_score = (SeverityWeight * 0.4) + (ConfidenceWeight * 0.3) + (EffortInversion * 0.3)`.
  * Generates concrete, step-by-step remediation plans with estimated byte and latency gains.

PHASE 6: HEADLESS BROWSER AUDIT VIA PLAYWRIGHT CHROMIUM
- Isolated ephemeral web server (`EphemeralProjectServer`):
  * Dynamically acquires an available high-range TCP port on 127.0.0.1.
  * Mounts the version's extracted folder as a sandboxed document root in a background thread.
- Browser test runner (`BrowserPerformanceRunner`):
  * Launches headless Chromium sandbox.
  * Navigates to `http://127.0.0.1:<ephemeral_port>/<entry_point>`.
  * Hooks into CDP and page event listeners to record network requests and JavaScript console errors.
  * Evaluates window performance APIs in page context:
    `performance.getEntriesByType('paint')` -> FCP
    `PerformanceObserver` -> LCP, CLS
    `performance.getEntriesByType('navigation')` -> TTFB, DOMContentLoaded, Load Event
  * Records individual resource duration, transfer size, and timeline start times for waterfalls.
- Calculates holistic `performance_score` (0-100) combining CWV thresholds with failed request penalties.

PHASE 7: VERSION COMPARISON & PRINTABLE REPORT ENGINE
- Version diff service (`VersionComparator`):
  * Compares any two project releases (Base vs Target / Before vs After).
  * Safely handles pending states without triggering template errors.
  * Computes delta improvements:
    - Payload size delta (+/- KB)
    - Core Web Vitals metric deltas (FCP, LCP, CLS, Load Event)
    - Resolved findings (issues fixed in target)
    - Regressions / new findings (issues introduced in target)
- Standalone Printable Report Generator (`ReportGenerator`):
  * Generates self-contained, CSS-styled HTML audit dossiers with sticky print toolbars.
  * Embedded print stylesheet (`@media print`) format tailored for A4 PDF export.
  * JSON export route (`GET /reports/<version_id>/json`) for machine consumption.

PHASE 8: COMPREHENSIVE QA & DEMO SEEDER
- Sample project seeder (`seed_demo_portfolio`):
  * Instantly creates a realistic sample project: "Solaris Green Energy Portfolio".
  * Creates `v1.0 (Unoptimized Base)`: Render-blocking scripts, uncompressed 2.8 MB PNGs, 
    missing viewport tag, missing image dimensions.
  * Creates `v2.0 (Optimized Release)`: Deferred scripts, modern compressed WebP images, 
    responsive viewport, explicit image dimensions.
  * Enables immediate testing of all graph, comparison, and audit views with a single click.
- Automated Pytest test suite: 29 tests covering all blueprints, models, services, 
  and error conditions.

9. STATIC ANALYSIS ENGINE & HEURISTIC RULES
================================================================================
WebPulse's `StaticAnalyzer` inspects source code using 12 deterministic rules:

RULE ID                    CATEGORY        SEVERITY   TRIGGER CONDITION
--------------------------------------------------------------------------------
HTML-RENDER-BLOCKING-JS    Performance     Critical   <script src="..."> in <head> without
                                                      'defer' or 'async' attribute.
HTML-NO-VIEWPORT           SEO / Mobile    Critical   Missing <meta name="viewport"> tag in
                                                      HTML document head.
HTML-NO-TITLE              SEO             Warning    Missing or empty <title> tag.
HTML-IMG-NO-ALT            Accessibility   Warning    <img> tag missing 'alt' attribute.
HTML-IMG-NO-DIMENSIONS     Performance     Warning    <img> tag missing 'width' or 'height'
                                                      (causes Cumulative Layout Shift).
CSS-SYNCHRONOUS-IMPORT     Performance     Critical   @import url(...) found in CSS file
                                                      (serializes network requests).
CSS-OVERSIZED-INLINE-B64   Performance     Warning    Data URI base64 payload in CSS
                                                      exceeding 8,192 bytes.
CSS-NO-FONT-DISPLAY        Performance     Info       @font-face declaration missing
                                                      'font-display: swap'.
JS-DOCUMENT-WRITE          Best Practices  Critical   Usage of document.write() found.
JS-SYNC-XHR                Performance     Critical   Synchronous XMLHttpRequest detected.
ASSET-OVERSIZED-RASTER     Performance     Warning    Single raster image (PNG/JPG) exceeding
                                                      1,048,576 bytes (1 MB).
ASSET-UNCOMPRESSED-MEDIA   Performance     Info       Presence of legacy BMP or uncompressed
                                                      WAV files.

10. HEADLESS BROWSER AUDIT & NAVIGATION TIMING API
================================================================================
WebPulse uses Playwright Chromium to measure true browser runtime dynamics:

1. CORE WEB VITALS (CWV):
   - First Contentful Paint (FCP): Time when browser renders the first piece of DOM 
     content (text, image, svg). Thresholds: <=1.8s (Good), <=3.0s (Moderate), >3.0s (Poor).
   - Largest Contentful Paint (LCP): Render timestamp of the largest visible content element.
     Thresholds: <=2.5s (Good), <=4.0s (Moderate), >4.0s (Poor).
   - Cumulative Layout Shift (CLS): Sum of all layout shift scores occurring during page 
     lifecycle. Thresholds: <=0.1 (Good), <=0.25 (Needs Imp), >0.25 (Poor).

2. NETWORK TIMING API DATA:
   - TTFB (Time to First Byte): `responseStart - requestStart`.
   - DOMContentLoaded Event: `domContentLoadedEventEnd - navigationStart`.
   - Load Event Duration: `loadEventEnd - navigationStart`.
   - Transfer Size: Raw bytes transferred across the simulated wire.

3. CONSOLE & EXCEPTION TRACING:
   - Captures unhandled JavaScript exceptions, network 404s, and console errors directly 
     from the Chromium CDP log stream.

11. VERSION COMPARISON & DELTA ENGINE
================================================================================
The `VersionComparator` service performs relational diffing between two `ProjectVersion` 
entities:

1. PAYLOAD DIFFERENTIAL:
   `size_diff_bytes = v_target.total_size_bytes - v_base.total_size_bytes`
   Categorized as byte reduction (green) or byte regression (amber).

2. CODE QUALITY DIFFERENTIAL:
   - Resolved Findings: Issues existing in Base version but absent in Target version.
   - Regressions / New Findings: Issues absent in Base version but introduced in Target version.
   - Persistent Findings: Issues present across both versions.

3. RUNTIME PERFORMANCE DIFFERENTIAL:
   - `score_delta = score_target - score_base`
   - `fcp_delta = fcp_target - fcp_base`
   - `lcp_delta = lcp_target - lcp_base`
   - `cls_delta = cls_target - cls_base`
   - `load_delta = load_target - load_base`
   - Graceful fallback: If either version lacks completed audits, the UI safely renders 
     informational badges with direct action buttons to trigger missing audits.

12. SECURITY ARCHITECTURE & ANTI-ZIP-SLIP DEFENSE
================================================================================
WebPulse implements defense-in-depth measures against untrusted file uploads:

1. ANTI-ZIP-SLIP DEFENSE (`app/services/archive_validator.py`):
   When users upload a ZIP archive, attackers could craft malicious entries such as:
   `../../../../etc/passwd` or `../../app/routes.py` to overwrite system or application files.
   
   WebPulse enforces the following mathematical containment check for every member:
   ```python
   def _is_safe_path(target_directory: Path, member_path: str) -> bool:
       resolved_target = target_directory.resolve()
       resolved_member = (target_directory / member_path).resolve()
       return resolved_member.is_relative_to(resolved_target)
   ```
   If any member attempts to escape `resolved_target`, extraction is immediately halted, 
   all temporary files are deleted, and an explicit security alert is logged.

2. STORAGE SEPARATION:
   Extracted files are stored in `storage/extracted/user_<id>/` outside the web application's 
   static directory. Files are never directly executable as PHP/CGI on the main server.

3. EPHEMERAL PROCESS ISOLATION:
   Browser audits execute against an ephemeral loopback server on a randomized port with 
   strict execution timeouts (20 seconds), terminating hung worker threads automatically.

15. GLOSSARY OF TECHNICAL TERMS & METRICS
================================================================================
- AST (Abstract Syntax Tree): A tree representation of source code structure used 
  by compilers and static analyzers to identify patterns without code execution.
- Anti-Zip-Slip: Security validation that ensures archived paths cannot escape the 
  intended extraction directory via relative `../` directory traversal.
- CLS (Cumulative Layout Shift): Core Web Vital measuring visual stability; quantifies 
  how often content shifts unexpectedly on screen during page load.
- Cytoscape.js: Open-source graph theory library for visualization and analysis of 
  network structures.
- Ephemeral Port: A temporary, dynamically allocated high-number TCP port (e.g. 54321) 
  used for short-lived communications.
- FCP (First Contentful Paint): Timestamp at which the browser renders the first piece 
  of text, image, or non-white canvas.
- Headless Browser: A web browser without a graphical user interface, controlled 
  programmatically for automated testing and performance profiling.
- LCP (Largest Contentful Paint): Timestamp at which the largest above-the-fold content 
  element is fully rendered.
- Navigation Timing API: Standard W3C interface providing high-resolution timestamps 
  for every phase of web page retrieval and rendering.
- TTFB (Time to First Byte): Latency between the browser initiating the HTTP GET request 
  and receiving the first byte of response data from the server.
- Waterfall Timeline: Visual horizontal chart displaying the sequence, start time, 
  duration, and concurrency of all HTTP resource requests during page load.
